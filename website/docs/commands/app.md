These commands manage and generate Flutter application projects within your FSDA workspace under the `apps/` directory.

---

## gen-app

```bash
fsda gen-app <app> [--org <org>] [--name "<App Name>"] [--org-name "<Organization Name>"]
```

Generates a new Flutter application project inside the `apps/` directory using `flutter create` combined with the FSDA Architecture app blueprint bundle.

### Naming Constraints

* **Format**: Must follow strict lowercase rules without separators (e.g., `adminapp`, `userportal`).
* **Validation**: Names containing uppercase letters, hyphens, spaces, or starting with invalid characters will be rejected immediately with an error.

### Options

* `--org <org>`: **(Optional)** Specifies the organization identifier in reverse-domain format (e.g., `com.example`). Defaults to `com.example`.
* `--name "<App Name>"`: **(Optional)** Specifies the title or display label of the app. Defaults to the app name identifier.
* `--org-name "<Organization Name>"`: **(Optional)** Specifies the organization display name. Defaults to the last segment of the organization identifier.

### What Happens

1. **Validates Input & Options**: Checks whether `<app>` and `--org` comply with strict naming and reverse-domain validation rules.
2. **Flutter Project Creation**: Executes `flutter create --org <org> <app>` inside the `apps/` workspace directory.
3. **Cleanup Default Test**: Automatically removes the default `test/` directory generated by Flutter.
4. **App Blueprint Generation**: Generates and overwrites files using the built-in Mason app bundle blueprint.
5. **Android Gradle Configuration**: Automatically updates `android/app/build.gradle.kts` (`compileSdk`, `minSdk`, and `targetSdk`) to sync seamlessly with the global workspace configuration defined in `fsda.yaml`.
6. **Dependency Installation**: Automatically installs required core `dependencies` (`logging`, `flutter_bloc`, `get_it`, `go_router`, `collection`, `intl`) and `dev_dependencies` (`flutter_lints`, `flutter_launcher_icons`, `package_rename`).
7. **Operation Report**: Displays a clean, structured terminal summary logging all created, overwritten, and configured paths.

### Rerun Behavior

- If an app directory with the same name already exists under `apps/`, the command halts execution immediately with an error and leaves existing files untouched.

### Examples

#### 1. Basic Generation

Creates a new app with default settings (`com.example` organization):

```bash
fsda gen-app adminapp
```

**Resulting Structure:**

* Path: `apps/adminapp/`
* App Identifier: `adminapp`
* Display Name: `adminapp`
* Organization: `com.example`

#### 2. Custom Organization and App Title

Creates a new app with a specific reverse-domain organization identifier and custom display names:

```bash
fsda gen-app portal --org com.fdelux --name "User Portal" --org-name "Flutter Delux"
```

**Resulting Structure:**

* Path: `apps/portal/`
* App Identifier: `portal`
* Display Name: `User Portal`
* Organization: `com.fdelux`
* Organization Name: `Flutter Delux`

## configure-app

```bash
fsda configure-app <project>
```

Configures an existing application project inside `apps/<project>` by injecting active workspace infrastructure packages (`infra_*`), updating `pubspec.yaml`, and setting up dependency injection entry points (`external_di.dart` and `core_di.dart`).

### Naming Constraints

* **Format**: Must follow strict lowercase rules matching an existing application under `apps/` (e.g., `portal`, `adminapp`).

### Workspace Guard

Must be executed inside an FSDA workspace root directory where `fsda.yaml` is present.

### What Happens

1. **Validates Target App**: Checks whether the targeted application directory (`apps/<project>`) physically exists on disk.
2. **Reads Workspace Configuration**: Reads `fsda.yaml` to extract all active infrastructure packages (packages prefixed with `infra_`).
3. **Injects Infrastructure Dependencies**:
   * Reads package bundle specifications for active `infra_*` packages.
   * Injects path dependencies pointing to `packages/infra_*` into `apps/<project>/pubspec.yaml`.
   * Triggers `dart pub add` for required external app dependencies declared by active infra packages.
4. **Injects External Dependency Injection (`external_di.dart`)**:
   * Injects required imports into `apps/<project>/lib/core/di/external_di.dart`.
   * Injects external DI initialization code inside the `externalDI()` function.
5. **Injects Core Dependency Injection (`core_di.dart`)**:
   * Injects required imports into `apps/<project>/lib/core/di/core_di.dart`.
   * Injects core DI registration code inside the `coreDI()` function.
6. **Operation Report**: Displays a terminal summary detailing all modified files and injected configurations.

### Rerun Behavior

* **Idempotent & Safe**: If dependencies or DI registrations already exist, they will be skipped, ensuring running `configure-app` multiple times will not duplicate dependencies or code injections.

### Usage Example

```bash
fsda configure-app portal
```
